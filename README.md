# Install-MicrosoftStore: установка и восстановление Microsoft Store в Windows 10 / 11

PowerShell-скрипт, который устанавливает **Microsoft Store** там, где его нет:

- в редакциях **LTSC / LTSB / IoT LTSC**, где Store отсутствует вообще (ни самого приложения, ни его компонентов);
- в **Home / Pro / Pro for Workstations / Education / Enterprise (включая N и KN)**, если Store был удалён или сломан (оптимизаторы, «debloat»-скрипты, ручное удаление пакетов, повреждённый образ).

Скрипт сам определяет версию Windows, пробует несколько способов установки, скачивает подходящий набор пакетов, ставит зависимости и сам Store и по желанию добавляет его в образ системы для новых пользователей.

> **Важно.** LTSC намеренно выпускается без Store, и Microsoft такую конфигурацию не поддерживает. Всё, что вы делаете этим скриптом, вы делаете на свой риск. Проект неофициальный и не связан с Microsoft.

## Возможности

- Запуск **одним файлом**: скрипт сам запрашивает права администратора и не закрывает окно, пока вы не прочитаете результат.
- **Безопасен на системах, где Store уже есть:** скрипт сообщает об этом и завершается, ничего не меняя.
- Несколько способов установки с автоматическим переходом к следующему, если предыдущий не сработал.
- Наборы пакетов **под конкретную версию Windows**: самый свежий Store подходит не ко всем сборкам.
- **Проверка подписи** каждого пакета (издатель должен быть Microsoft Corporation) до установки.
- Кэш скачанных пакетов, повторные попытки загрузки, подробный журнал.
- Установка с лицензиями и добавление в образ системы (Store появится у новых учётных записей).
- Оффлайн-режим: установка из своей папки с пакетами.

## Поддерживаемые системы

### Редакции

| Редакция | Что делает скрипт |
|---|---|
| **LTSC / LTSB / IoT LTSC** (Windows 10 и 11) | Основной сценарий: полная установка Store с нуля. |
| **Pro, Pro for Workstations, Enterprise, Education** | Store обычно уже есть, и скрипт ничего не меняет. Если Store удалён или не зарегистрирован, восстанавливает его. |
| **Home**, а также **N / KN** | То же, что для Pro. |
| Windows Server | Не поддерживается и не тестировалось. |
| Windows 7 / 8.1 / Windows 10 старше 1607 | Не поддерживается. |

Для обычных редакций сначала попробуйте штатные средства: **Параметры → Приложения → Microsoft Store → Дополнительные параметры → Исправить / Сбросить** или команду `wsreset -i` от администратора. Скрипт нужен, когда они не помогают или Store удалён полностью.

### Сборки и наборы пакетов

| Сборки (build) | Примеры систем | Набор Mirror |
|---|---|---|
| 14393 – 19043 | Windows 10 1607 (LTSB 2016), 1809 (LTSC 2019), 1903 – 21H1 | `LTSC2019` |
| 19044 – 21999 | Windows 10 21H2 (LTSC 2021, IoT LTSC 2021), 22H2 | `LTSC2021` |
| 22000 – 26099 | Windows 11 21H2 – 23H2 | `LTSC2021` (пакеты для Windows 10, должны подойти) |
| 26100 и выше | Windows 11 24H2 и новее (LTSC 2024, IoT LTSC 2024) | `Win11_24H2` |

Архитектуры: **x64** (основная), x86 (только Windows 10), ARM64 (только Windows 11).

### Статус проверки

Синтаксис скрипта проверен парсером PowerShell, вспомогательные функции проверены на тестовых данных. Полная установка зависит от доступности источников и конкретной сборки, поэтому сюда стоит записывать результаты реальных запусков:

| Система | Результат |
|---|---|
| LTSB 2016 (14393) | не проверено |
| LTSC 2019 (17763) | не проверено |
| LTSC 2021 (19044) | не проверено |
| LTSC 2024 (26100) | не проверено |
| Windows 10 Pro / Home, Store удалён | не проверено |
| Windows 11 Pro / Home, Store удалён | не проверено |

Если вы запускали скрипт, откройте Issue с версией Windows и результатом.

## Быстрый старт

1. Скачайте `Install-MicrosoftStore.ps1`.
2. Если файл скачан из интернета, откройте **Свойства** и поставьте галочку **«Разблокировать»** (или выполните `Unblock-File .\Install-MicrosoftStore.ps1`).
3. Щёлкните по файлу **правой кнопкой мыши**, выберите **«Выполнить с помощью PowerShell»** (в Windows 11 пункт находится в «Показать дополнительные параметры»).
4. На вопрос об изменении политики выполнения нажмите `Y` (изменение действует только на этот запуск).
5. В окне UAC нажмите **«Да»**. Установка продолжится в новом окне.
6. Дождитесь сообщения «Microsoft Store установлен» и нажмите Enter. Если Store не запускается сразу, перезагрузите компьютер.

Открыть Store: меню «Пуск» или `Win+R` → `ms-windows-store:`.

### Запуск из командной строки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-MicrosoftStore.ps1
```

Запуск должен идти **из файла**. Вариант `irm ... | iex` не поддерживается: самоповышение прав требует пути к файлу скрипта.

### Необязательный `.cmd`-лаунчер

Если правая кнопка на вашей системе не работает (например, групповая политика блокирует пункт меню), создайте рядом файл `Install-MicrosoftStore.cmd` и запускайте его двойным кликом:

```bat
@echo off
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%~dp0Install-MicrosoftStore.ps1" %*
if errorlevel 1 pause
```

Параметры, добавленные после имени `.cmd`, передаются в скрипт.

## Параметры

| Параметр | Описание |
|---|---|
| `-PackagePath <папка>` | Установить из локальной папки с пакетами (`.appx`, `.msix`, `.appxbundle`, `.msixbundle`). |
| `-Source Auto\|StoreCdn\|Mirror` | Источник загрузки. По умолчанию `Auto`. |
| `-ManifestUrl <https-адрес>` | JSON-манифест для источника `Mirror`. По умолчанию `https://files.w3k.dev/msstore/manifest.json`. |
| `-NoDownload` | Ничего не скачивать из сети (только имеющееся, `-PackagePath` и кэш). |
| `-ForceDownload` | Не использовать кэш, скачать пакеты заново. |
| `-SkipWsreset` | Пропустить способ `wsreset -i`. |
| `-WsresetTimeout <сек>` | Сколько ждать `wsreset -i` (30–900, по умолчанию 180). |
| `-CurrentUserOnly` | Ставить только текущему пользователю, не добавляя Store в образ системы. |

Примеры:

```powershell
# Обычная установка или восстановление
.\Install-MicrosoftStore.ps1

# Принудительно использовать подобранные наборы (рекомендуется для LTSC 2019 / LTSB 2016)
.\Install-MicrosoftStore.ps1 -Source Mirror

# Домашний или рабочий ПК: восстановить Store только себе, без добавления в образ системы
.\Install-MicrosoftStore.ps1 -CurrentUserOnly

# Оффлайн-установка из заранее подготовленной папки
.\Install-MicrosoftStore.ps1 -PackagePath D:\StorePackages -NoDownload
```

## Как это работает

Скрипт выполняет способы по порядку и останавливается, когда Store появился:

1. **Проверка.** Если Store уже установлен для текущего пользователя, скрипт сообщает об этом и завершается, ничего не меняя.
2. **Подготовка.** Службы `InstallService`, `ClipSVC`, `AppXSvc`, `wuauserv` и `LicenseManager` переводятся из «Отключена» в «Вручную» и запускаются.
3. **Регистрация имеющихся файлов.** Если файлы Store остались в системе (типично для Home/Pro), они регистрируются через `AppXManifest.xml`.
4. **`wsreset.exe -i`.** Штатная установка из интернета, только для Windows 11 (сборка 22000+).
5. **Локальная папка** (`-PackagePath`).
6. **Кэш** ранее скачанных пакетов.
7. **Загрузка из сети** (источники ниже).

Для каждого найденного набора пакетов сначала ставятся зависимости (VCLibs, NET.Native, UI.Xaml), затем Store, StorePurchaseApp и вспомогательные приложения. Если не включён `-CurrentUserOnly`, пакеты дополнительно добавляются в образ системы (`Add-AppxProvisionedPackage`), чтобы Store был у новых пользователей.

### Источники загрузки

| Источник | Откуда берёт | Особенности |
|---|---|---|
| `StoreCdn` | Список ссылок формирует сервис `store.rg-adguard.net`, сами файлы скачиваются с CDN Microsoft | Всегда самые свежие версии. Сам сервис сторонний. Для старых LTSC свежий Store может не подойти. |
| `Mirror` | JSON-манифест (по умолчанию community-зеркало `files.w3k.dev`) | Наборы пакетов подобраны под версию Windows, есть файлы лицензий. Зависит от одного стороннего домена. |
| `Auto` | `StoreCdn`, затем `Mirror` | На Windows 10 сборки ниже 19041 порядок обратный: сначала `Mirror`. |

Прямых официальных ссылок на сам пакет Store Microsoft не публикует, поэтому полностью обойтись без посредников нельзя. Для максимального контроля можно скачать пакеты самостоятельно и поставить через `-PackagePath`.

### Безопасность

- Перед установкой скрипт проверяет подпись каждого пакета: статус должен быть `Valid`, издатель — `Microsoft Corporation`. Пакеты с чужой или повреждённой подписью отбрасываются, скачанные такие файлы удаляются.
- Если статус подписи определить не удалось, скрипт предупреждает об этом, а окончательную проверку выполняет система развёртывания Windows.
- Разрешены только адреса: `*.microsoft.com` (для `StoreCdn`; ссылки там могут быть по HTTP, целостность обеспечивает проверка подписи), а для `Mirror` — HTTPS-хост манифеста, `aka.ms` и `*.microsoft.com`.
- Манифест `Mirror` загружается только по HTTPS.
- Проверка подписи не заменяет доверие к источнику. Читайте код скрипта и используйте `-PackagePath`, если нужен полный контроль.

### Что скрипт меняет в системе

- Устанавливает пакеты `Microsoft.WindowsStore`, `Microsoft.StorePurchaseApp` и сопутствующие (зависимости, при источнике `StoreCdn` также `Microsoft.DesktopAppInstaller` и `Microsoft.XboxIdentityProvider`).
- Если Store ещё не установлен, включает перечисленные выше службы (меняет тип запуска с «Отключена» на «Вручную»). Если вы намеренно отключили, например, Windows Update, учтите это.
- Создаёт папку `%ProgramData%\MicrosoftStore-LTSC-Installer` (кэш и журнал).
- Без `-CurrentUserOnly` добавляет пакеты в образ системы (Store появится у новых пользователей).

## Формат манифеста для `Mirror`

Корневые ключи — наборы под версию Windows: `Win11_24H2` (сборка 26100+), `LTSC2021` (19044+), `LTSC2019` (14393+). Все адреса должны быть HTTPS.

```json
{
  "LTSC2021": {
    "deps": [
      "https://example.com/Microsoft.VCLibs.x64.14.00.Desktop.appx",
      "https://example.com/Microsoft.VCLibs.x86.14.00.Desktop.appx"
    ],
    "store": "https://example.com/Microsoft.WindowsStore_...msixbundle",
    "store_license": "https://example.com/Microsoft.WindowsStore_....xml",
    "StorePurchaseApp": "https://example.com/Microsoft.StorePurchaseApp_...msixbundle",
    "StorePurchaseApp_license": "https://example.com/Microsoft.StorePurchaseApp_....xml"
  }
}
```

Из `deps` скрипт берёт файлы, подходящие по архитектуре: на x64 это `x64` и `x86`, на ARM64 — `arm64` и `x86`, на x86 — только `x86`. Поля `StorePurchaseApp` и `*_license` необязательны.

## Оффлайн-установка

На ПК с интернетом скачайте в одну папку:

- `Microsoft.WindowsStore` (`.msixbundle`) и его лицензию (`.xml`);
- `Microsoft.StorePurchaseApp` (`.msixbundle`) и лицензию (по желанию);
- зависимости: `Microsoft.VCLibs.140.00`, `Microsoft.NET.Native.Framework`, `Microsoft.NET.Native.Runtime`, `Microsoft.UI.Xaml` под вашу архитектуру.

Перенесите папку на нужный ПК и запустите:

```powershell
.\Install-MicrosoftStore.ps1 -PackagePath D:\StorePackages -NoDownload
```

Скрипт выберет самые свежие версии по каждому пакету и поставит их в нужном порядке.

## Частые проблемы

**Скрипт пишет «Store уже установлен» и завершается.** Так и задумано: Store найден для вашей учётной записи. Если он не открывается, используйте «Исправить / Сбросить» в Параметрах или `wsreset -i`.

**Окно закрывается сразу после `Y`.** Убедитесь, что используете актуальную версию скрипта: в ранних вариантах была синтаксическая ошибка, из-за которой PowerShell завершался до запуска. Запустите из консоли, чтобы увидеть текст ошибки.

**Скрипт не запускается: «выполнение скриптов отключено» или «не имеет цифровой подписи».** Запускайте через `powershell -ExecutionPolicy Bypass -File ...` или `.cmd`-лаунчер. Если политика `AllSigned` задана групповой политикой, она может оказаться сильнее.

**Не появляется окно UAC.** Проверьте, что вы вошли под учётной записью администратора и что UAC не отключён политикой.

**Ошибка вида «требуется более новая версия Windows» при установке Store.** Для вашей сборки не подходит самый свежий Store. Запустите с `-Source Mirror`, чтобы взять набор, подобранный под вашу версию.

**Store установился, но не открывается или не скачивает приложения.** Перезагрузите компьютер и проверьте службы Windows Update, `InstallService` и `ClipSVC`. На сильно «вычищенных» сборках, где вырезаны компоненты обновления, Store может работать некорректно.

**Не удаётся войти в учётную запись Microsoft.** Проверьте дату, время и часовой пояс. Если вход всё равно не работает, ставьте дополнительно `Microsoft.XboxIdentityProvider` (в `StoreCdn` он скачивается автоматически).

**Источник недоступен.** Сторонние сервисы могут временно не работать или изменить формат. Повторите запуск позже, смените `-Source` или используйте `-PackagePath`.

## Удаление

Команды от имени администратора (на свой риск; удаление Store может повлиять на установленные из него приложения):

```powershell
Get-AppxPackage -AllUsers Microsoft.WindowsStore | Remove-AppxPackage -AllUsers
Get-AppxProvisionedPackage -Online | Where-Object DisplayName -eq 'Microsoft.WindowsStore' |
    Remove-AppxProvisionedPackage -Online
```
